# Local Phase 2 header changes

`vercel.json` contains local-only X-Frame-Options DENY, a restrictive unused-capability Permissions-Policy, and an enforced CSP candidate. No hosting setting was changed and nothing was deployed. Live headers therefore remain the Phase 1 baseline until the owner reviews and deploys these files manually.

The CSP allows the existing self-hosted assets, inline styles used by critical CSS/React, and the hash of the existing stylesheet-load handler `this.media='all'`. It restricts object, base and form destinations. The form also has its own SSR-disabled guard. There is no new reporting endpoint or third-party collector. The policy was first tested in report-only mode across 78 route/engine cases with zero policy-violation events after static-render repairs (`qa/after-phase2/iterations/report-only-csp/csp.json`). WebKit still warns that report-only mode has no reporting destination. The local candidate now enforces the same policy so compatibility can be tested without inventing a reporting endpoint; this has no effect on live hosting. No HSTS header is added to HTTP localhost; the live HTTPS host already supplies it.

Before owner deployment: review all browser violations and actual production resource origins, externalize remaining inline handlers or maintain accurate hashes/nonces, test all routes/states, and decide whether an approved reporting destination is wanted. Confirm DENY is compatible with the business's embedding needs. No application iframe embedding was found in the audited route tree; if approved embedding is needed later, replace DENY with a reviewed enforced frame-ancestors policy. COOP/CORP remain owner decisions rather than unconditional additions.

The audit preview reads only the common security headers from this local file so browser compatibility can be exercised; it does not emulate Vercel's edge caching, TLS, redirects or compression. Sources: [MDN report-only CSP](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/Content-Security-Policy-Report-Only), [MDN script hashes](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/Content-Security-Policy/script-src), [Vercel configuration](https://vercel.com/docs/project-configuration).

Static generation resolves nested lazy modules before a synchronous serialization pass, avoiding streaming reveal scripts and hidden fallback copies. This follows React’s [static rendering guidance](https://react.dev/reference/react-dom/static/prerenderToNodeStream); full HTML is retained without JavaScript. No inline script allowance was broadened.
